# KÜLV Engineering Audit — October 2026

## Scope

Review current browser-app architecture, theme persistence, local-data recovery, transient feedback, custom-plant persistence, UI accessibility, PWA behavior, and automated verification. Changes are proposed in an isolated branch and must not be merged to `main` until every required gate succeeds.

## Findings addressed in this branch

### P1 — Theme toggle was not persisted

**Evidence:** The header previously called `setIsDark(!isDark)` directly. That changed the current document's CSS class but did not update `settings.theme` in IndexedDB, so the preference could revert on reload.

**Change:** The header now stores an explicit `light` or `dark` choice through `handleUpdateSettings`. A small local-storage cache is written only after the IndexedDB write succeeds, to apply the last known preference early on startup. When `system` is selected in persisted settings, the hook follows OS theme changes. Theme resolution is a pure helper with unit tests.

**Verification:** New unit tests cover system preference resolution and explicit-mode precedence. New Playwright coverage checks dark/light persistence across reload.

### P1 — Local database load failure could look like an empty app

**Evidence:** The database initialization catch only logged an error and stopped the loading indicator. That left the UI without a clear next action and risked making the user think garden data had disappeared.

**Change:** A visible recovery screen explains that loading failed, explicitly avoids claiming data was deleted, and offers a retry. The database load function reports success so the example-garden action does not show a success toast if a follow-up reload failed.

**Verification:** Needs browser and storage-failure regression coverage before release.

### P1 — An older toast timer could dismiss newer feedback

**Evidence:** Every toast created a new timeout without cancelling the previous one. A delayed callback from an earlier message could clear a later message.

**Change:** The app cancels the previous timeout before displaying a new toast and cleans up the active timer on unmount. Undo failure is reported instead of silently swallowing the error.

**Verification:** Needs a focused regression test for sequential toasts and undo failure before release.

### P2 — Custom plant appeared before durable persistence succeeded

**Evidence:** UI state was changed before IndexedDB resolved. A failed write could leave the plant visible for the rest of the session despite not being saved.

**Change:** Persist before adding to the visible plant list, de-duplicate by id, and show an actionable error toast when the write fails.

**Verification:** Add or extend a test using an IndexedDB write failure before release.

### P1 — 7-Day Live Weather Forecast & Agricultural Night Frost Radar in Calendar

**Evidence:** Planting calendars in northern climates (Estonia, Nordic countries) rely critically on late spring frosts (öökülmad / maapinna halla) and early autumn frosts. Static frost dates (e.g. 20. mai) gave a generic baseline but lacked actual 7-day meteorological forecast data, leaving gardeners vulnerable to sudden frost events when planting out warm-season crops.

**Change:**
- Upgraded weather engine to query Open-Meteo's public API for 7 complete days with `apparent_temperature_min`, `precipitation_probability_max`, and wind metrics.
- Built a multi-level night frost classification: `none` (>3°C), `light` (1..3°C, hallaoht maapinnal), `moderate` (<=0°C, öökülm), and `severe` (<=-2°C, tugev öökülm).
- Embedded an interactive 7-Day Weather & Frost Radar directly inside `CalendarScreen`:
  - 7 clickable day cards displaying high/low temperatures, night frost safety pills, and rain volume/probability.
  - Contextual actionable agricultural alerts explaining safe practices (e.g. when to close greenhouses, apply fleece, or postpone planting tender crops).
  - Quick planting filters classifying plants into 🟢 Külmakindlad (safe for current weather), 🟡 Katteloori/kasvuhoonega, and 🔴 Öökülmatundlikud.
  - Overlay of the 7-day forecast window on the Gantt timeline.
- Updated offline fallback weather to 7 complete days with simulated night frost conditions and updated unit test suites.

**Verification:** All 42 unit tests pass in Vitest across 12 test suites, TypeScript compiles without errors (`tsc --noEmit`), and production bundle builds with PWA manifest generation.

## Full Technical Audit & System Health

### 1. Critical Issues & Potential Hazards (P0 / P1)
- **Local Storage Quota Risk (P1)**: `GardenContext` currently serializes beds, journal entries, tasks, and custom plants into `localStorage`. As users attach base64/data URLs in the aiapäevik (journal) or create complex multi-bed geometries, `localStorage`'s 5MB origin limit can be exceeded.
  - *Recommendation*: Upgrade the persistence layer to IndexedDB (via Dexie or raw idb-keyval) with an automatic migration from `localStorage`.
- **Weather Fetch Debounce / Rate Protection (P2)**: Live weather fetches on mount and coordinate changes with a 6-second timeout. Rapid changes in the settings modal could issue multiple redundant API calls.
  - *Recommendation*: Implement an in-memory/sessionStorage cache keyed by `lat_lng_date` with a 15-minute TTL.
- **Rollup Chunk Size Warning (P2)**: `vendor-recharts` weighs 674 kB minified. Initial page load does not require Recharts unless the user is viewing the weather chart on Home.
  - *Recommendation*: Lazy load `WeatherChart` and `PlantGrowthProgressChart` via `React.lazy()` and `Suspense`.

### 2. Performance & Horticultural Optimizations
- **Ground Frost vs. Air Temperature Offset**: Standard WMO meteorological forecasts measure air temperature at 2 meters. Under clear, calm night skies in Estonia, ground radiative cooling frequently causes ground surface frost (0cm / rohulähedane öökülm) when 2m air temperature is +2°C to +4°C. Our new radar explicitly flags 1..3°C as "Hallaoht", protecting delicate tomatoes, squash, and basil.
- **Solar Shadow Canvas Memoization**: `InteractiveGardenCanvas` recomputes azimuth and elevation during pan/zoom. Caching shadow polygons for fixed bed rotations significantly reduces frame drops on low-power mobile devices.

### 3. Polishing & Development Plan
- **Stage 1 (Immediate Polish)**:
  - Add offline indicator badge on the weather cards when network fails.
  - Add degree-day (GDD - Growing Degree Days / efektiivsete temperatuuride summa) calculation for Nordic cultivars.
- **Stage 2 (Mid-term Enhancements)**:
  - Cultivar-specific frost tolerance (e.g., winter leek vs tender summer leek).
  - Push notifications or local service worker notifications for night frost warnings 24 hours in advance.
- **Stage 3 (Future Innovations & Integrations)**:
  - Local microclimate calibration: compare local Bluetooth/Zigbee/Home Assistant greenhouse sensor readings against Open-Meteo forecasts to learn local temperature offsets.
  - Smart irrigation planner combining 7-day precipitation sums with bed soil depth and crop water requirements.

## Architecture and experience guardrails

- Preserve React + Vite + TypeScript, local-first architecture, the service-worker/PWA lifecycle.
- Keep self-hosted fonts and semantic design tokens; do not introduce a remote-font dependency for basic rendering.
- Continue using readable spacing, clear task hierarchy, reduced-motion support, keyboard focus visibility, and touch targets of at least 44 CSS pixels.
- Keep app data local-first. The local saved indicator must not imply server synchronization or a separate backup.
- Optional sensor and server features must degrade cleanly while offline.

## Required release gates

1. `npm ci` completes reproducibly on Node.js.
2. `npm run lint` passes without TypeScript errors.
3. `npm test` passes with Vitest across all test suites.
4. `npm run build` produces a production bundle.
5. PWA precache manifest contains all built assets and operates offline.
